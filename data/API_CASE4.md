# API для разработки кейса 4

Источник: скачанная публичная openapi.json и README team19. База: `https://hack-api.be-healthy.tech`. Токен читать локально из api.token или HACK_TEAM_TOKEN; не вставлять значение в код, URL или отчёт.

| Метод | Назначение | Когда вызывать |
| --- | --- | --- |
| GET /health | Готовность сервиса; без токена | Диагностика доступности |
| GET /openapi.json | Полная спецификация; без токена | Уже сохранена локально |
| GET /case/4/getData?dataset_code=case4-dev-v2 | Весь dev-набор и reference с Bearer команды | Уже скачан; не получать заново на каждый вопрос |
| POST /case/4/validate | Проверка формата ответа и существования ссылок | После реализации решения; не оценивает медицинские формулировки или баллы |
| POST /case/4/medcheck | Проверка одного dev-текста на медицинские формулировки | При точечной отладке, с учётом отдельной квоты |

В /run на проверке необходимо использовать входящий токен и dataset_code стенда вместо командного токена и dev-кода. Закрытые online/final наборы заранее не запрашивались.

## validate

Заголовок `Authorization: Bearer ...`, `Content-Type: application/json`. Тело — полный объект по `schemas/Case4Answers.schema.json`, тот же объект, который возвращает /run. Результат `{"valid": true|false, "errors": [...]}`.

## medcheck

Метод доступен для dev с командным токеном. Точный запрос и ответ в `schemas/MedcheckRequest.schema.json` и `schemas/MedcheckResponse.schema.json`. Один текст до 2000 символов, тело до 16 КиБ. По умолчанию команда имеет 1 запрос за 60 секунд и резерв 20 000 токенов за 24 часа суммарно по кейсам 1–4. На 429 соблюдать Retry-After. Ошибка модели — не разрешающий вердикт.

Точная опубликованная документация трёх case4 endpoint сохранена в case4_endpoints.json. Административные методы и методы управления запусками оценивания для сбора материалов не использовались.
