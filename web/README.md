# Frontend — SAIN, эксперт как плейлист

Мобильный веб-интерфейс для беседы о сне с сомнологом, биохакером и нутрициологом. Реализован на HTML, CSS и JavaScript (ES modules), без сторонних зависимостей. На широком экране сохраняется компактная колонка для чтения.

Основа — [два экрана макета Figma](https://www.figma.com/design/7WdwRmw1Inl85RYu8HlPLH/Untitled?node-id=0-1): выбор эксперта и беседа. Оформление восстановлено по видимому макету: тёмная тема, цветовые темы экспертов, карточки и поле ввода. Figma MCP не предоставил доступ к слоям/ресурсам, поэтому типографика и значки приближённые; иконки экспертов, знак в шапке и стрелка отправки встроены в страницу, шрифты системные. Строка состояния телефона и индикатор Home относятся к ОС и в веб-страницу не включены.

## Возможности

- Список экспертов из backend; если он недоступен, можно открыть экраны трёх стандартных экспертов для просмотра интерфейса. Ответы требуют рабочего backend; демонстрационные ответы не подставляются.
- Отдельный диалог с каждым экспертом. Перед первым вопросом клиент получает браузерный токен через `POST /session`, передаёт его в `Authorization: Bearer` и сохраняет `session_id` для следующих вопросов. Каждый новый диалог получает новую сессию.
- Enter отправляет сообщение, Shift+Enter вставляет перенос строки.
- Во время запроса повторная отправка заблокирована. При ошибке вопрос возвращается в поле ввода, автоматического повтора нет.
- Просмотр оригинального раздела статьи, авторов, года, DOI и лицензии через карточку источника.
- Отображение ограниченного ответа (`refused`), загрузки и ошибок сервера.
- Прослушивание ответа через Web Speech API, если браузер его поддерживает. Доступность русского голоса зависит от устройства. Браузер/ОС может использовать сетевой синтез речи; он запускается только по нажатию пользователя.
- Новый диалог создаёт новую сессию. Диалоги хранятся только в памяти вкладки; после перезагрузки история интерфейса исчезает. Backend хранит свою историю в памяти процесса.

## Локальный запуск

Нужен Node.js 18+; `npm install` не требуется.

Если в окружении доступен `node`, но отсутствует `npm`, используйте эквивалентные команды из `web`: `node scripts/dev.mjs`, `node scripts/build.mjs`, `node --test tests/api.test.mjs`.

Из корня репозитория:

```powershell
cd web
npm run dev
```

Открыть http://127.0.0.1:5173. Dev-сервер отдаёт файлы из `src` и проксирует `/experts`, `/session`, `/chat`, `/source/...` на backend (по умолчанию http://127.0.0.1:8000). Фактически прокси пропускает только перечисленные в скрипте клиентские пути. Сохранив изменения, обновите страницу.

Чтобы использовать другой локальный backend:

```powershell
$env:BACKEND_URL = 'http://127.0.0.1:9000'
npm run dev
```

`BACKEND_URL` используется только Node-сервером и должен быть HTTP URL. Dev-сервер слушает только loopback; для публикации используйте FastAPI.

Backend находится в этом же репозитории; его настройка описана в [BACKEND.md](../docs/BACKEND.md). На Windows после установки `requirements.txt` можно запустить:

```powershell
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Для рабочих ответов backend нужны серверные переменные `HACK_API_URL`, `HACK_TEAM_TOKEN`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. В локальном режиме задайте `DEV_DATASET_CODE=case4-dev-v2`; на стенде данные загружаются через организаторский `/run`. До загрузки данных `/experts` возвращает 503, и интерфейс показывает сообщение с кнопкой проверки подключения. Для Windows также задайте `CASE4_INDEX_PATH` в существующем доступном каталоге, например `tmp/case4-index.sqlite3` (предварительно создайте `tmp`).

Ключи и токены остаются на сервере. Клиент не вызывает организаторский `/run`, не содержит credentials и не подменяет реальный ответ демонстрационным. Вопросы в `/chat` расходуют общую квоту LLM.

## Сборка для стенда

```powershell
cd web
npm run build
npm test
```

Сборка копирует четыре файла из `src` в `dist`. `web/dist` включается в Git: стенд устанавливает только Python-зависимости и не запускает Node.js. После сборки перезапустите backend — `backend/app.py` подключает статические файлы при импорте приложения. Интерфейс будет доступен на `/`, API — по тем же путям и на том же origin; отдельный CORS не требуется.

## API

| Запрос | Использование |
|---|---|
| `GET /experts` | `{experts: [{expert_id, role, speech_style}], dataset_generation}` |
| `POST /session` | выдаёт `{session_id, token, user_id, expires_in}` для браузера |
| `POST /chat` | с `Authorization: Bearer <token>`: `{expert_id, message, session_id?, turn_id?}` → `{session_id, expert_id, text, refused, citations, turn_id, dataset_generation}` |
| `GET /source/{article_id}/{section_id}?generation=...` | заголовки, текст раздела, авторы, год, DOI, лицензия |

`user_id` интерфейс не задаёт: текущий backend выбирает первого пользователя датасета. Браузерный токен отделён от организаторского токена `/run` и от ключа LLM; клиент не может выбрать пользователя или датасет. Приложение рассчитано на хакатонный стенд, многопользовательскую изоляцию backend не обеспечивает. Для сервиса с реальными аккаунтами потребуется отдельная серверная модель пользователей и сессий. `turn_id` генерируется на каждый вопрос и сохраняется при автоматическом пересоздании сессии, поэтому такой повтор не создаёт второй ответ. `dataset_generation` из цитаты передаётся в `/source`, чтобы не показать раздел из другого датасета.

Список экспертов ожидается до 15 секунд; при долгой инициализации данных можно повторить проверку подключения. Ответ чата ожидается до 310 секунд с учётом загрузки корпуса и генерации. Клиент не показывает поток токенов: `/chat` возвращает целый ответ. Текст ответа и источников выводится через `textContent`, HTML из модели не выполняется. Закрыть источник можно кнопкой или Escape.

## Структура и проверка

```text
web/src/              исходники интерфейса и API-клиент
web/dist/             готовые файлы для FastAPI
web/scripts/build.mjs сборка без зависимостей
web/scripts/dev.mjs   локальный сервер с API-прокси
web/tests/            тесты API-клиента без вызова LLM
```

`npm test` проверяет выдачу сессии, тело запросов и bearer-токен, кодирование ID источников и generation, сетевые/серверные ошибки и таймаут. Реальные ответы LLM и качество медицинских выводов эти проверки не оценивают.

При разработке пройдены все три теста API-клиента. В браузере на синтетическом локальном API проверены выбор эксперта, отправка вопроса, безопасный вывод HTML как текста, открытие источника, возврат вопроса после 503, новый диалог и экран шириной 390 px. Синтетический сервер не входит в frontend и не используется приложением. Backend-тесты в текущем окружении не смогли импортировать `fastapi`; 25 тестов RAG прошли. Реальный LLM не вызывался.
