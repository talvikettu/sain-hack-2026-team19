# Оптимизация RAG после первого прогона

## Что показал реальный прогон

Первые 10 вопросов: 12 вызовов, 69 754 токена, из них вход — 60 916, выход с reasoning — 8838. При таком же среднем расходе 60 вопросов потребовали бы около 418 524 токенов, выше общего дневного лимита 300 000. Это экстраполяция одного прогона, не измерение всех 60.

Старая оценка 8/10 означала только допустимость выбранных article_id по dev-reference. Она не подтверждает, что 8 ответов хороши. Вопросы №1/№6 получили неправильные статьи; №7/№10 — тематически правильную статью, но вводный фрагмент вместо достаточных результатов. В ответах биохакера были придуманные сроки наблюдения. Медицинская проверка, полнота ответа и различимость персон не оценивались автоматически.

## Изменения

| Компонент | Раньше | Теперь, профиль compact |
|---|---|---|
| Инструкции | Полный system + полный локальный persona + описание роли из API + повторные правила | Короткий system_compact.md + одно описание роли/стиля из API |
| Контекст | До 5 фрагментов, 12 000 символов | До 3 фрагментов, 4500 символов |
| История | До 6 сообщений на каждом вопросе | Только при явной отсылке к истории, до 4 сообщений/2000 символов |
| Выход LLM | Полные record_id и объекты citations, inline-дубли ID | text/refused/refs с номерами; реальные ID и record_id собирает код |
| Поиск | Расширение всех совпавших слов | Приоритет явного фактора, расширенный словарь, умеренный приоритет результатов/выводов |
| Максимум completion | 2500 | 1800, включая reasoning |

Короткий refs-контракт уменьшает расходы и риск синтаксических ошибок ссылок. Это не проверка научной релевантности. Снижение max_tokens само по себе не уменьшает уже короткий ответ и может привести к truncation; проверка finish_reason сохранена.

Старые промпты сохранены; `--profile full` позволяет сравнить старую сборку. Никакого нового LLM-перевода, классификатора или reranker-вызова не добавлено.

## Измерения без LLM

Подготовлены все 60 dev-запросов в обоих профилях:

| Метрика | full | compact |
|---|---:|---:|
| Суммарные символы инструкций | 749 640 | 150 420 |
| Суммарные символы данных | 508 560 | 228 900 |
| Всего символов | 1 258 200 | 379 320 |
| Среднее на запрос | 20 970 | 6322 |

Сокращение текста — **69.9%**. Это не измерение токенизатором модели и не обещание экономии общего расхода на 69.9%: выход и скрытые рассуждения остаются. В этих 60 вопросах текущая эвристика не обнаружила явных отсылок к истории; это не доказательство отсутствия неявных зависимостей.

Offline retrieval: хотя бы одна статья из допустимых по dev присутствует в контексте 57/60 вопросов; все статьи контекста допустимы для 54/60. До изменения — хотя бы одна для 39/60. Эти результаты получены на наборе разработки, который использовался при настройке; это не независимая оценка на новых вопросах и не точность ответов. Reference в запросы к модели и индекс не включается.

Локальные материалы: `tmp/token_optimization/comparison.json`, `tmp/token_optimization/retrieval_checks.json`, `tmp/token_optimization/compact/preview.json`. Реальные старые ответы сохранены отдельно в `tmp/rag_demo_first10/` и не перезаписаны.

## Проверки и следующий контроль

25 тестов проходят: старый и короткий форматы, преобразование refs, отклонение несуществующих ссылок, выбор эксперта, сохранение источников между персонами, изоляция истории, парсинг/чанки/индексы и клиентские лимиты.

Новых вызовов модели при оптимизации не выполнялось. Перед полным live-прогоном требуется небольшой фактический замер usage с новым профилем и ручная проверка качества. Нельзя считать объём символов надёжным показателем оставшегося дневного бюджета. CLI по умолчанию ограничен локальным бюджетом 120 000 токенов; он может остановить 60-вопросный прогон раньше конца. Общие расходы других участников команды неизвестны.

Остающиеся риски: небольшая RU→EN эвристика, выбор только одного основного фактора в многотемном вопросе, пропуск неявной связи с историей, неполный контекст, медицинская корректность и качество стиля. Их нужно проверять отдельно, не компенсируя отсутствующие доказательства длинным промптом.
